# ClassRelay 실제 장비 검증표

[English](acceptance.md)

자동 테스트는 실제 화면 송수신, WebSocket 복구, Windows 입력 잠금 검증을 대체하지 않는다. 아래 항목의 기본 상태는 모두 **미실시**다. 회사 소유 교육 장비에서 수행한다.

## 전제 조건

잠금 모드가 포함된 첫 검사 전에 아래를 끝낸다.

1. **그 교실의 현장 담당자에게 `Ctrl+Shift+F12`를 안내한다.** 어떤 모드에서도 학생 화면은 이 단축키를 표시하지 않도록 설계되어 있으므로, 교실 안의 누구도 소프트웨어를 통해 이를 알 수 없다. 배려가 아니라 필수 전제다.
2. **`nativeInputLock`은 장비별로 의도적으로 켠다.** 생성된 설정은 `false`이며, 꺼진 상태에서 잠금 모드는 오버레이만 띄울 뿐 아무것도 억제하지 않는다. 그런 장비에서의 잠금 시험은 아무것도 증명하지 못한다. 어느 장비에서 켰는지 기록한다.
3. **장비마다 자기 `deviceId`에 묶인 고유 토큰을 준다.** 토큰 하나를 여러 장비에 복제하면 아래 인증 검사가 무의미해진다.
4. **강사 쪽에서 수업을 끝내는 방법을 숙지하고**, 학생 앱 종료가 단방향임을 인지한다. 학생 앱을 원격으로 다시 켜는 수단은 없다.

## 검증 항목

| 단계 | 수행 | 합격 기준 |
|---|---|---|
| 1대 | 강사와 학생을 서로 다른 Wi-Fi에 둔다 | 화면 선택 후 학생에 영상 표시 |
| 1대 | 인증 WebSocket 확인 | 연결 직후 상태 수신, 정상 동작에서 REST 상태 폴링 없음 |
| 1대 | 화면 보여주기 (`broadcast`) | 강사 화면 전체화면, 작업 표시줄 덮임. 학생 입력은 여전히 자유롭고 Alt+Tab이 동작 — 의도된 동작이다 |
| 1대 | 이론 모드 (`lecture`) | 강사 화면이 전체화면으로 전혀 가려지지 않음. 입력 차단. 학생 화면 어디에도 상태 문구·통계·단축키 안내 없음 |
| 1대 | 강사 주목 (`lock`) | 영상이 의도적으로 가려짐. 입력 차단. 가림막은 강사를 보라고만 안내하고 어떤 키 조합도 적지 않음 |
| 1대 | 정상 상태의 학생 화면 침묵 확인 | `broadcast`·`lecture`·`lock`에서 아무 장애가 없으면 학생에게는 영상만 보임. 오버레이도 실측값도 없음 |
| 1대 | 잠금 모드 → 실습 (`practice`) | 입력 복구. 잔류 창·kiosk·키 억제 없음 |
| 1대 | 송출 중 공유 화면 교체 | 학생이 끊김 없이 계속 시청. 녹색 `송출 중` 배지가 새 화면으로 이동. 모드 변경 없고 잠금이 걸리거나 풀리지 않음 |
| 1대 | 교체 실패 (캡처 선택창 취소) | 이전 화면이 계속 송출됨. 강사 메시지 줄에 실패가 표시됨 |
| 1대 | `lecture` 또는 `lock` 중 강사 영상 경로를 멈춘다 | 수 초 안에 입력이 해제됨. 학생 화면에 프리즈 해제 문구 표시. 더 높은 revision의 새 명령 전까지 해제 상태 유지 |
| 1대 | 학생 Wi-Fi 끄기 | 마지막 유효 제어 상태 이후 약 15초 안에 해제 |
| 1대 | 강사 앱 강제 종료 | 강사 lease 만료 후 학생 해제 |
| 1대 | 학생 렌더러 종료 | native watchdog 유지 및 잠금 해제 |
| 1대 | 각 잠금 모드에서 비상 단축키 | 즉시 해제, 같은 revision으로 재잠금 없음 |
| 1대 | 망 단절 뒤 재연결 | 새 상태 적용, 만료·비상 해제 revision으로 재잠금 없음 |
| 1대 | 잠든 PC 깨우기 | 과거 잠금 적용 없이 새 push 상태 연결·수신 |
| 1대 | 로그아웃 후 로그인 | 설정된 Agent 자동 시작 및 연결 |
| 1대 | 학생 앱 종료 | 학생 앱이 입력 guard와 kiosk를 해제한 뒤 정상 종료. 보고된 `notified` 수가 연결 장비 수와 일치. **3초 뒤 작업 관리자에 `ClassRelay` 프로세스가 남아 있지 않음** |
| 1대 | 학생 장비 한 대에서 `run.bat`을 두 번 실행 | 인스턴스가 정확히 하나만 유지됨. 강사 명단에 그 장비가 한 번만 보이고 깜빡이지 않음 |
| 1대 | 강사 장비에서 `run.bat`을 두 번 실행 | 기존 창이 앞으로 옴. 두 번째 강사 연결이 생기지 않음 |
| 1대 | 화면 캡처 선택창을 10초 넘게 취소·방치 | 메시지 줄에 캡처 시간 초과가 표시되고 모드 버튼이 다시 눌리며 모드는 전송되지 않음 |
| 1대 | 종료 명령 **이후에** 학생 앱을 시작 | 그 장비는 정상 연결되고 종료되지 **않음**. 강사에게 다른 장비를 원격으로 다시 켤 수단이 없음을 확인 |
| 인증 | 잘못된 토큰, device ID 누락, 다른 학생의 device ID | 401/403, 제어 상태 변경 없음 |
| 인증 | 학생이 mode 변경이나 종료 명령 시도 | 403, 제어 상태 변경 없음 |
| 망 제한 | UDP 제한 환경 | TURN 활성화 후 연결 확인. `/api/ice`가 사용 가능한 서버 목록 반환 |
| 3대 | Wi-Fi와 모바일 핫스팟 혼합 | 개별 장애가 다른 학생에게 영향 없음 |
| 10대 | broadcast·lecture·lock·practice 반복 전환, 1시간 | 즉시 명령 전달과 스트림·프로세스 증가 없는 안정적 복구 |
| 30대 | 5시간 soak, 반복 해제 및 재연결 | 잠금 잔류 없음. Realtime·Workers·Durable Objects 사용량 기록 |
| 용량 | 실제 수업 중 Controller의 실측 송출 줄을 읽는다 | 실제 해상도·프레임률·비트레이트를 기록하고, 계산으로 만든 용량 추정치를 이 값으로 대체 |

## 순서와 보고

강제 종료·망 단절·비상 해제를 1대에서 통과시킨 뒤 3대, 10대, 30대로 확장한다. `nativeInputLock`이 `false`인 장비에서 수행한 잠금 항목은 잠금 검사가 아니라 표시 검사다. 그렇게 기록한다.

실제 결과는 [검증 기록](verification.ko.md)에 남기되 실배포 실측·실장비 관측·미검증 항목을 각각 다른 절에 적는다.
